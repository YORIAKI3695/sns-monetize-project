# 将来の年間リピート鑑定対応設計(STEP9)

## 1. 基本方針(🟢確定仕様)

[[02_Method/波動鑑定メソッド仕様書_v0.1|SSOT]] 第7章の通り、リピーター対応時のフローは以下を厳守する。

1. 顧客ID(`customer_id`)から既存顧客かを判定
2. 既存顧客であれば `life_waves`(人生3大波動)を**再利用**し、再計算しない
3. 当年度の `annual_readings` を新規に1レコード追加算出する
4. 前年度の `annual_readings` と比較し、変化を鑑定に含める

## 2. リピーター判定フロー(🟡仮仕様)

```
顧客情報入力(LINE/フォーム)
  → customer_id 検索(氏名+生年月日等での照合 🔴要検討: 照合キーの厳密な設計)
  → 既存顧客が見つかった場合:
        life_waves を取得(再計算しない)
        当年の annual_readings が既に存在するか確認
          → 存在する場合: 重複購入か再鑑定希望かを確認するフローが必要 🔴要検討
          → 存在しない場合: 新規算出へ
  → 新規顧客の場合:
        life_waves を新規算出
        当年の annual_readings を算出
```

🔴 **要検討**: 氏名の表記ゆれ・同姓同名等を考慮した顧客照合ロジック(単純な氏名+生年月日一致では不十分な可能性)。将来的にはLINEのユーザーIDや会員登録IDとの紐付けが望ましいと考えられるが、初期の手動運用段階の照合方法は未設計。

## 3. 前年比較ロジック(🔴要設計)

- `annual_readings.previous_year_comparison` として、前年の `wave_score` / `wave_level` / `theme` との差分を保持する案([[05_Database/データベース設計書]] 参照)
- 比較の見せ方(鑑定書内での表現)は [[07_Certificate/PDF鑑定書仕様書]] 側で設計
- 🔴 要検討: 差分の意味づけ(例: 前年よりレベルが上がった場合にどう文章化するか)の具体的なテンプレートは未作成

## 4. calculation_version 更新時の扱い(🔴要検討・SSOT側の未決定事項と連動)

メソッド仕様([[02_Method/波動鑑定メソッド仕様書_v0.1]])が `v0.1` から `v0.2` 等に更新された場合の選択肢:

- 案A: 既存顧客の `life_waves` は再計算しない(算出時のバージョンのまま固定)。新規顧客のみ新バージョンを適用
- 案B: 全顧客の `life_waves` を新バージョンで一括再計算する
- 案C: 顧客の希望があれば個別に再計算を提供する(有償/無償は別途検討)

→ **要決定**。現時点ではSSOTは「人生3大波動は原則固定」という原則のみを定めており、上記いずれの案を採用するかはプロジェクトオーナーの判断待ち。

## 5. 複数年蓄積時のデータ活用(🟡仮仕様・将来構想)

- 顧客が10年、20年と継続した場合、`annual_readings` の時系列データを使って「人生の波動グラフの長期推移」を鑑定書に表示することが可能になる
- 将来的な追加商品(例: 「10年間の振り返り鑑定」)の材料になり得るが、現時点では商品化していない(🔴要検討・将来構想)

## 6. 通知・リマインド設計(🔴要検討・未着手)

- 前年鑑定を受けた顧客に対し、翌年の更新時期をどう案内するか(LINE配信のタイミング・頻度)は未設計
- 自動化の最終形([[08_Automation/自動化フロー設計書]])のリピーターフローと連動して今後設計する
