# データベース設計書(STEP4)

> 最重要原則([[02_Method/波動鑑定メソッド仕様書_v0.1|SSOT]] 第6章): **`life_waves`(固定)と `annual_readings`(年次追加)を絶対に混同しない。**

## 1. テーブル一覧(🟡仮仕様・型は要検討)

### customers(顧客マスター)

| カラム | 型(仮) | 説明 |
|---|---|---|
| customer_id | UUID/PK | 顧客ID |
| name | string | 氏名 |
| birth_date | date | 生年月日 |
| birth_time | time, nullable | 出生時間(不明の場合はnull) |
| birth_time_unknown | boolean | 出生時間不明フラグ 🔴要検討: nullとの併用要否 |
| birth_place | string | 出生地(地名) |
| birth_place_lat / birth_place_lng | float, nullable | 出生地座標(占星術計算用) 🔴要検討: ジオコーディング方式 |
| birth_place_timezone | string, nullable | 出生地タイムゾーン 🔴要検討 |
| current_occupation | string, nullable | 現在の仕事(追加情報) |
| current_concern | enum/string | 今一番気になっていること(仕事/お金/恋愛結婚/人間関係/独立起業/その他) |
| created_at | timestamp | 登録日時 |

### life_waves(人生3大波動・固定データ)

| カラム | 型(仮) | 説明 |
|---|---|---|
| life_wave_id | UUID/PK | |
| customer_id | UUID/FK | customers参照 |
| wave_1 / wave_2 / wave_3 | jsonb または個別カラム | 第1波・第2波・第3波(スコア・時期・元占術データ等を含む構造) 🔴要検討: 内部構造 |
| calculation_version | string | 算出時のメソッドバージョン([[02_Method/波動鑑定メソッド仕様書_v0.1]] のバージョンと対応) |
| created_at | timestamp | 算出日時 |
| recalculated_at | timestamp, nullable | 再計算した場合の日時(原則発生しない想定) |

**運用ルール(🟢確定仕様)**: 顧客あたり原則1レコード。再計算は原則行わない([[00_Project/01_不明点・矛盾点・不足情報一覧]] D-12の方針決定待ち)。

## 2. 追加提案テーブル(🟡仮仕様)

構想書に明記はないが、SSOTおよび他設計書の要件を満たすために必要と考えられる。

### wave_score_config(波動スコア設定・バージョン管理)

鑑定ロジックのパラメータ(重み付け・変換表・閾値)をコード外で管理するための設定テーブル。

| カラム | 説明 |
|---|---|
| config_version | バージョン識別子(`calculation_version` と対応) |
| weights | 占術ごとの重み付け(jsonb) |
| score_mapping | 生データ→スコアの変換ルール(jsonb) |
| sync_thresholds | 一致判定の閾値(jsonb) |
| level_thresholds | 5段階レベルの閾値(jsonb) |
| effective_from | 適用開始日 |

→ [[04_Wave_Calculation/鑑定ロジック設計書]] 第8章の「パラメータ外部化」を実現するテーブル。

### fortune_source_data(占術生データ・監査用)

各占術エンジンが算出した生データ(大運、トランジット、個人年など)をそのまま保存し、後から再検証・再計算できるようにする。

| カラム | 説明 |
|---|---|
| customer_id / year(nullable) | 人生3大波用は年度なし、年間波用は年度あり |
| method | 四柱推命/西洋占星術/数秘術/他 |
| raw_data | 生データ(jsonb) |
| created_at | |

### life_events(人生の転換点・メソッド検証用)

顧客が入力する過去の転換点データ。鑑定にも、将来のメソッド検証にも使用する([[00_Project/01_不明点・矛盾点・不足情報一覧]] D-13)。

| カラム | 説明 |
|---|---|
| customer_id | |
| age_or_year | 出来事があった年齢または年 |
| event_description | 出来事の内容(例: 就職、結婚、独立) |
| event_type | best_period / hardest_period / turning_point 等の分類 |

### products(商品マスター)

| カラム | 説明 |
|---|---|
| product_id | |
| name | 商品名 |
| price | 価格(🔴要検討: 29,800円は仮価格) |
| includes_stone | パワーストーン付きか |

### stone_recommendations(パワーストーン提案・上位商品用)

| カラム | 説明 |
|---|---|
| annual_reading_id | 対応する年間鑑定 |
| theme | 鑑定テーマ |
| recommended_stone | 提案する石 🔴要検討: テーマ→石のマッピング表が未作成 |
| positioning_note | 「必ず効果がある」等の断定を避けた説明文 |

### consent_logs(個人情報同意ログ)

[[12_Security/セキュリティ・個人情報管理設計書]] と連動。取得目的への同意記録。

## 3. ER概要(テキスト表現)

```
customers 1───* life_waves        (原則1顧客につき1レコード)
customers 1───* annual_readings   (1顧客につき年度分だけレコードが増える)
customers 1───* life_events
customers 1───* orders ───1 products
customers 1───* documents ───(0..1) annual_readings
annual_readings 1───* stone_recommendations
(customers/annual_readings) 1───* fortune_source_data
wave_score_config は customers に直接紐付かず、calculation_version 経由で life_waves / annual_readings と対応
```

## 4. 個人情報の取り扱いに関する設計上の注意(🔴要検討)

`customers` テーブルの `name` `birth_date` `birth_time` `birth_place` は要保護情報として扱う。暗号化・アクセス制御・保持期間の方針は [[12_Security/セキュリティ・個人情報管理設計書]] 側で定義し、本テーブル設計はその方針に従って実装時に調整する。
